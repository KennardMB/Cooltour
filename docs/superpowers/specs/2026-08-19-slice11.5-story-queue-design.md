# Slice 11.5 — Story queue (design)

**Date:** 2026-08-19  
**Branch:** `feature/slice11-consent-gate` (continues Slice 11)  
**Status:** approved — implement

## Goal

Third consent answer: **Add to queue** — *"not now, but play it after what I’m hearing."*

## Product rules (locked)

1. Playing site A + approach site B → **pause A** only while B’s spoken prompt plays; when TTS
   ends, **resume A immediately** (even if she hasn’t answered yet) and start the 10s dismiss
   countdown. Play / Dismiss / Add to queue remain available while A continues.
2. **Play now** → stop A, play B immediately.
3. **Dismiss** (tap or timer) → drop B; A keeps playing if it already resumed.
4. **Add to queue** → enqueue B; A keeps playing; when A finishes, **auto-play** the next queued
   story (no second prompt).
5. After the **spoken prompt finishes**, start a **10s** dismiss countdown; at 0 → auto-dismiss.
   Any answer cancels the timer immediately.
6. Queue is in-memory for the current walk only — **clear when walking mode turns off**. De-dupe by story slug. No persistence across walks.
7. While already prompting, a further busy trigger → **enqueue silently** (no second spoken prompt).

## Architecture (approach B)

| Piece | Responsibility |
|---|---|
| `StoryQueue` | Ordered list, de-dupe, enqueue / remove / clear / `popNext()` |
| `ConsentNarrationCoordinator` | Pause/resume, three answers, post-speech dismiss timer; calls queue |
| `PromptVoice` | Speaks prompt; signals `onFinished` so the 10s timer can start |
| Now UI | Add to queue, countdown on Dismiss, queue list |

`StoryQueue` does not own consent UI or TTS. The coordinator does not own long-lived list storage.

## Types

- `QueuedStory` — value type: `id`, site/story slugs + titles (`Sendable`, UI-safe).
- `PromptOutcome.queued` — history resolution for queue answers (and silent busy enqueues).
- `AppConfig.dismissCountdownSeconds = 10` (replaces starting the old 20s timer at speak-start).

## Protocol additions

```text
StoryQueue: items, enqueue(site:story:), remove(id:), clear(), popNext() -> Story?
NarrationCoordinator: queue(promptID:), dismissCountdownSeconds: Int?
PromptVoice: onFinished: (() -> Void)?
```

## State notes

- `wasPausedForPrompt` (coordinator-private): true when a prompt interrupted playback; resume only on dismiss/queue.
- `playbackDidFinish`: if queue has items, `popNext()` and play; else → `idle`.
- Stem still maps only to **Play now**.

## Out of scope

- Notification “Add to queue” (Slice 13)
- Persist / reorder queue
- Queueing anything that was never proximity-triggered

## Acceptance

- Queue from prompt plays nothing yet; resumes paused story; history → `queued`.
- Overlapping approach while playing → one prompt + pause; queue then auto-plays after finish.
- Silent enqueue while already prompting; de-dupe by slug.
- 10s after speech ends → dismiss + resume if paused.
- Walking mode off clears queue.
- Unit tests cover ordering, de-dupe, busy path, play-next, countdown dismiss.
